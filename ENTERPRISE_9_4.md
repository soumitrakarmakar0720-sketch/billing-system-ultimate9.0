# Enterprise 9.4 staging
Includes 9.1 plus initial 9.2–9.4 features. Before starting the new app, back up the database and run `flask --app app upgrade-enterprise` once using the target database environment. This creates four new tables only. Existing terminal sessions must log in again. Existing staff can be assigned branches; historical bills are not backfilled. Branches are reporting labels, not authorization boundaries. Terminal status is heartbeat-based and requires refresh of the control page. Revocation does not cancel gateway payments already open. Customer profiles use exact name and phone, not a verified identity. No new environment variables. Test on separate staging database with Cashfree sandbox. Syntax and template parsing checked; runtime and payment regression tests pending.
